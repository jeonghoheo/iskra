HOW IT WORKS

An agent is, in the end, one well-built loop

Around the heart of the system — a loop where the model alternates between answers and tool calls — the brain, the tools and the logs attach loosely. Each file owns exactly one role, so the code stays easy to read and to change.

STEP 1 · BRAIN

Ask the brain

brain.rs sends the conversation and the tool list to the DeepSeek API and brings the reply back.

STEP 2 · LOOP

The loop decides

loop_.rs separates a final answer from a tool call — and enforces the guardrails.

STEP 3 · TOOLS

Tools execute

File reads and writes in tools.rs work only inside workspace/.

STEP 4 · LOG

Everything is logged

Even token usage lands in logs/agent.log as hard numbers.

FEATURES

Small — but with hard boundaries

Three criteria chose Iskra's shape: lightweight, directly customisable, and structured so it could one day be sold. What is already built and what comes next are labelled honestly.

A loop that knows when to stop Done

Stop conditions are hard-coded as constants, so the agent cannot spin forever. When the model repeats the same mistake, the agent stops first.

MAX_ROUNDS = 10 · SAME_ERROR = 2
TIMEOUT = 60s · EMPTY_RETRY = 1

Sandboxed file tools Done

Reads and writes live only inside the workspace/ folder. Even if the model force-calls a path outside, the code refuses — fail-closed.

read_file · write_file
Boundary verified by 4 unit tests

SANDBOX

Not “please don't” — “can't”

Safety that lives in a prompt ends the moment the model disobeys it. Iskra puts the path checks in code, so there is simply no way out.

  • ✓
    Absolute paths refusedOnly paths relative to the workspace are accepted.
  • ✓
    “..” segments blocked outrightParent-directory escapes are stopped before normalisation.
  • ✓
    Symlinks resolved to real locationsIf the real location behind a link is outside, the call is refused.
  • ✓
    Unverifiable = refused (fail-closed)A broken link that cannot be judged is never opened.
src/tools.rs — boundary check (concept excerpt)
fn resolve_in_workspace(path) -> Result<PathBuf> {
  // 1. Absolute paths are refused from the start
  if path.is_absolute() { return Err("rejected") }
  // 2. Any '..' segment blocks the call outright
  if path.has_parent_traversal() { return Err("rejected") }
  // 3. Resolve links; the real location must stay inside
  let real = canonicalize(path)?; // failure = refusal
  if !real.starts_with(workspace) { Err("rejected") }
}

QUICKSTART

Five minutes to your first conversation

All you need is Rust and a DeepSeek API key. Put the key in .env only — and never commit it to the repository.

# 1) Clone the repository
git clone https://github.com/jeonghoheo/iskra.git
cd iskra

# 2) Add your DeepSeek key (.env is gitignored)
cat > .env << 'EOF'
DEEPSEEK_API_KEY=your_key_here
EOF

# 3) Run — the first build compiles dependencies and may take a few minutes
cargo run
No Rust yet? Install it with rustup first. 
// The minimal circuit from Block 2 — ask DeepSeek one sentence, print the answer
use serde_json::json;

#[tokio::main]
async fn main() -> Result<(), Box<dyn Error>> {
    dotenvy::dotenv().ok();
    let key = env::var("DEEPSEEK_API_KEY")?;

    let body = json!({
        "model": "deepseek-chat",
        "messages": [{ "role": "user",
          "content": "Introduce yourself in one sentence" }]
    });

    let res = Client::new()
        .post("https://api.deepseek.com/chat/completions")
        .bearer_auth(key).json(&body).send().await?;
    let v: Value = res.json().await?;
    println!("{}", v["choices"][0]["message"]["content"]);
    Ok(())
}
