# Iskra (Искра)

**Лёгкий персональный ИИ-агент, написанный с нуля на Rust.**
*Искра* — это та самая маленькая искра, с которой всё начинается.

Iskra — персональный агент, который живёт в мессенджере, запоминает сказанное сразу и помнит после перезапусков, использует инструменты в строгих границах разрешений и спроектирован так, чтобы его можно было разбирать и собирать заново: модель, канал или инструменты меняются без изменения ядра.

> **Статус:** v1 завершена и проходит тестирование в личном использовании. Цикл ядра, файловые инструменты, память и канал Telegram уже работают.
> В этом репозитории только код — личная память, данные и секреты здесь никогда не хранятся.

## Принципы проектирования

1. **Лёгкость по бюджету, а не по надежде** — один бинарный файл с жёсткими лимитами на размер, память в простое и число зависимостей; измерения на каждом релизе.
2. **Модульность по контрактам** — мозг, канал, инструменты и память спроектированы так, чтобы соединяться версионированными спецификациями интерфейсов (`brain/v1`, `channel/v1`, `tool/v1`, `memory/v1`); в коде спецификации формализуются в v2. Расширение — это добавление частей, а не правка ядра.
3. **Безопасность fail-closed** — инструменты работают внутри папки-песочницы; инструмент shell допускает только перечисленные программы, подкоманды и аргументы, запускается с очищенным окружением, а на macOS — внутри песочницы ОС без доступа к сети; учётные данные маскируются перед сохранением в память; одобрение человеком необратимых действий запланировано на v2.
4. **Дисциплина затрат** — (в планах) повторяющаяся работа кристаллизуется в процедуры, которые выполняются без вызова модели; дорогие чувства (экран) — последнее средство, сначала структурированные каналы (API · DOM).
5. **Память, которую можно читать** — долговременная память — обычный Markdown с бюджетом загрузки, маскированием секретов при сохранении и защитой от заражения — пока в виде правил для модели; структурный карантин для внешнего контента запланирован на v2.

## Дорожная карта

| Версия | Направление |

| v1 | Персональный агент для одного пользователя (Telegram, один мозг, пять инструментов, память в Markdown) |
| v2 | Сменные части — формализация контрактов, несколько мозгов, маршрутизация через модель решений |
| v3 | Делегированная работа — триггеры, пакеты ботов, спецификация идентичности (`identity/v1`) |

## Быстрый старт

```bash
git clone https://github.com/jeonghoheo/iskra.git
cd iskra
cp .env.example .env   # добавьте ключ API модели (LLM_API_KEY — любой провайдер; по умолчанию DeepSeek)
cargo run
```

Чтобы добавить второго агента, создайте локальный `iskra.json` в рабочей папке, из которой запускается Iskra (формат — в `docs/ARCHITECTURE.md` §12). Без `iskra.json` Iskra работает с одним агентом `main`, как раньше. Один каталог данных обслуживает только один процесс Iskra: второй процесс завершается до вызова модели или записи состояния. Рабочая и памятная папки дополнительного агента должны быть настоящими каталогами, производными от ID (`agent-workspaces/<id>/`, `memory/agents/<id>/`); символические ссылки и пути, указывающие на `main`, другого агента или наружу, отклоняются при запуске.
