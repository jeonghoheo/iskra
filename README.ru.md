# Iskra (Искра)

[English](README.md) | **Русский** | [한국어](README.ko.md)

![Iskra mascot](assets/iskra-mascot.gif)

**Лёгкая, независимая от модели среда выполнения агентов с долговечными запусками, написанная на Rust.**
*Искра* — это та самая маленькая искра, с которой всё начинается.

Iskra — персональная среда выполнения агентов с долговечными запусками, явной маршрутизацией, читаемой памятью и строгими границами инструментов. Прерванная работа не повторяется автоматически после перезапуска; модель, канал и инструменты можно менять без переноса полномочий из Core.

> **Статус:** v1 и v2 завершены. Среда с двумя агентами, долговечная очередь задач и явная маршрутизация, Stage 2.5-A, надёжная доставка (`delivery/v1`), и минимальная внешняя поверхность отправки/чтения (`headless/v1`) реализованы и проверены. Outcome/Evidence, ACP, делегирование, более широкая Headless Control Plane (BYOUI) и маршрутизация через модель решений пока не реализованы и остаются целями за отдельными проверками спроса, безопасности и готовности к реализации.
> В этом репозитории только код — личная память, данные и секреты здесь никогда не хранятся.

## Принципы проектирования

1. **Лёгкость по бюджету, а не по надежде** — один бинарный файл с жёсткими лимитами на размер, память в простое и число зависимостей; измерения на каждом релизе.
2. **Модульность по контрактам** — мозг, канал, инструменты и память спроектированы так, чтобы соединяться версионированными спецификациями интерфейсов (`brain/v1`, `channel/v1`, `tool/v1`, `memory/v1`); в коде спецификации формализуются по мере появления каждой части. Расширение — это добавление частей, а не правка ядра.
3. **Безопасность fail-closed** — инструменты работают внутри папки-песочницы; инструмент shell допускает только перечисленные программы, подкоманды и аргументы, запускается с очищенным окружением, а на macOS — внутри песочницы ОС без доступа к сети; учётные данные маскируются перед сохранением в память; одобрение человеком необратимых действий ещё не реализовано и остаётся за более поздней проверкой спроса.
4. **Дисциплина затрат** — (в планах) повторяющаяся работа кристаллизуется в процедуры, которые выполняются без вызова модели; дорогие чувства (экран) — последнее средство, сначала структурированные каналы (API · DOM).
5. **Память, которую можно читать** — долговременная память — обычный Markdown с бюджетом загрузки, маскированием секретов при сохранении и защитой от заражения — пока в виде правил для модели; структурный карантин для внешнего контента остаётся более поздней целью.

- [x] Цикл диалога с условиями остановки (лимит кругов инструментов, остановка при повторяющейся ошибке)
- [x] Файловые инструменты (`read_file`, `write_file`), ограниченные папкой `workspace/`
- [x] Память в Markdown с бюджетной загрузкой и маскируемым сохранением, перечитывается на каждом сообщении (без перезапуска), файлы идентичности (SOUL.md / USER.md)
- [x] Канал Telegram с белым списком отправителей
- [x] Инструмент shell (`ls`, `cat`, `git`, `cargo`) с политикой подкоманд и аргументов, очищенным окружением и песочницей macOS (где песочницы ОС нет, cargo отключён) + проверенная задача по программированию
- [x] Усиление shell (v1.1): закрыто 21 обходной путь, все покрыты тестами
- [x] Среда с двумя агентами (Stage 2): локальный реестр `iskra.json` (не больше двух агентов), отдельные модель, инструменты, память, сессия, рабочая папка и учёт расходов у каждого агента, долговечная очередь задач в `memory/runs.json`, явная маршрутизация `@agent`, команды `/agents`, `/status [@agent]`, `/stop [@agent]`, `/resume [@agent]`, пометка `@имя` в ответах другого агента
- [x] Stage 2.5-A, надёжная доставка (`delivery/v1`) — автоматические проверки и проверка владельцем пройдены: отслеживание `pending`·`sent`·`failed`·`unknown`, durable recovery без автоматического повтора, локализованные счётчики `/status`, `/result <run-id>` без вызова модели. Последующие Outcome/Evidence, ACP, делегирование, более широкая Headless Control Plane и продуктовые поверхности требуют отдельных проверок спроса и допусков к реализации
- [x] Минимальная внешняя поверхность отправки/чтения (`headless/v1`) — три loopback-эндпоинта с токеном владельца и идемпотентной отправкой; после перезапуска работа остаётся `interrupted` без повторного выполнения; автоматические проверки и реальный smoke-тест внешнего клиента с настоящим провайдером пройдены, затем поверхность заморожена

## Дорожная карта

| Этап | Направление |
|---|---|
| v1 | Персональный агент для одного пользователя (Telegram, один мозг, пять инструментов, память в Markdown) |
| v2 | Сменные части — готово: среда с двумя агентами, долговечная очередь, явная маршрутизация, надёжная доставка (`delivery/v1`) и минимальная внешняя поверхность `headless/v1` |

Дальнейшие направления открываются по проверкам спроса, а не по расписанию версий — без прохождения проверки направление не начинается.

| Направление | Проверка | Содержание |
|---|---|---|
| Agent Replay & Delivery Audit | Готовы форма приёма, путь оплаты и репетиция с замером времени | Платный аудит инцидента фиксированного объёма через существующий путь CLI/Run/Session/Delivery |
| Outcome/Evidence + один Outcome Pack | Два платных аудита с одной повторяющейся потребностью или один платный пилот | Минимальный `outcome/v1` и детерминированный `evidence/v1` |
| ACP и ограниченное делегирование | Платное доказательство, что встроенный HTTP-агент не справляется с проверенной работой | Внешние движки за брокером одобрения |
| Managed, постоянная работа | Реальный платный пилот и отдельный проект безопасности и эксплуатации | Однотенантный хостинг и подписанные релизы |
| Team / самостоятельная мультитенантность | Повторяющаяся выручка Managed | Позже; мультитенантность по пользователям сейчас не планируется |

## Быстрый старт

```bash
git clone https://github.com/jeonghoheo/iskra.git
cd iskra
cp .env.example .env   # добавьте ключ API модели (LLM_API_KEY — любой провайдер; по умолчанию DeepSeek)
cargo run
```

Чтобы добавить второго агента, создайте локальный `iskra.json` в рабочей папке, из которой запускается Iskra (формат — в `docs/ARCHITECTURE.md` §12). Без `iskra.json` Iskra работает с одним агентом `main`, как раньше. Один каталог данных обслуживает только один процесс Iskra: второй процесс завершается до вызова модели или записи состояния. Рабочая и памятная папки дополнительного агента должны быть настоящими каталогами, производными от ID (`agent-workspaces/<id>/`, `memory/agents/<id>/`); символические ссылки и пути, указывающие на `main`, другого агента или наружу, отклоняются при запуске.
